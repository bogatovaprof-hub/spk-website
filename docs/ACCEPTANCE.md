# Приёмка прототипа

Этот checklist должен выполнить разработчик после реализации. Наличие checklist в пакете не означает, что сайт уже создан и прошёл тесты.

## A. Соответствие главной

- [ ] Светлая палитра, тёмно-синие заголовки, синие кнопки; тёмный макет не использован.
- [ ] Все семь зон идут в правильном порядке; нет добавленных блоков, которых нет на утверждённой главной.
- [ ] H1, слоган, абзац и обе CTA совпадают с `home.json`.
- [ ] Четыре факта не переименованы и не дополнены.
- [ ] Восемь карточек услуг, правильные фото, подписи и порядок.
- [ ] «Все услуги» ведёт в каталог десяти услуг.
- [ ] В панели формы те же два инженера; нет картинки с нарисованными полями вместо HTML.
- [ ] Два специальных направления используют точные исходные фото и подписи.
- [ ] Header/footer без лишних фиктивных сведений.
- [ ] Ни один крупный блок страницы не подменён цельным screenshot.

## B. Тексты и маршруты

- [ ] Все 22 маршрута из routes.json созданы; обычные страницы доступны напрямую.
- [ ] Услуги используют исходные абзацы, а не новые выдуманные SEO-статьи.
- [ ] Для гидроизоляции отсутствует broken image; нет подмены чужой фотографией.
- [ ] Есть заметная связь бетонных и полимерных полов.
- [ ] FAQ содержит все шесть вопросов и исходные ответы.
- [ ] «Проекты» открывается; фиктивного портфолио нет.
- [ ] Нет выдуманных цен, сроков, объёмов строительства, телефонов, адресов и реквизитов.
- [ ] Служебные JSON-поля не видны пользователю.
- [ ] Пустые/служебные страницы честно обозначены как состояние прототипа.

## C. Адаптивность

Проверить **360 × 800, 390 × 844, 768 × 1024, 1122 × 900, 1440 × 1000**. Размеры выбраны для тестирования, а не заявлены как исходные размеры устройств.

- [ ] `document.documentElement.scrollWidth <= window.innerWidth + 1` на основных страницах.
- [ ] Текст не обрезается и не перекрывает кнопки/фото.
- [ ] На узком экране доступно меню; все пункты видимы после открытия.
- [ ] Четыре факта переходят в 2 × 2; карточки услуг перестраиваются без карусели.
- [ ] Форма, прикреплённые длинные имена файлов, ошибки и CTA не ломают ширину.
- [ ] Кнопки и поля удобны для нажатия; текст формы на телефоне 16 px, чтобы не провоцировать нежелательное увеличение в отдельных браузерах.
- [ ] На 200% масштабе браузера основные действия остаются доступными.

## D. Взаимодействия

- [ ] Все пункты header, footer, карточки и CTA ведут на правильную страницу/действие.
- [ ] Нет ссылок `href="#"`, `javascript:void(0)` и кнопок без поведения.
- [ ] Диалог открывается и закрывается; Escape, возврат фокуса, Tab работают.
- [ ] Меню не оставляет страницу заблокированной после закрытия.
- [ ] FAQ раскрывается с клавиатуры; ответы доступны в HTML.
- [ ] Форма показывает ошибки имени, телефона, некорректного e-mail.
- [ ] При исправлении ошибок данные не теряются.
- [ ] Файл выбирается, имя/размер отображаются, отдельный файл удаляется.
- [ ] Проверяются ограничения расширения, количества и размера.
- [ ] Валидный submit показывает «Это прототип: заявка и файлы не отправлены».
- [ ] Submit не вызывает внешние запросы и не пишет данные в localStorage/console.
- [ ] Контакты-плейсхолдеры не инициируют звонок/отправку письма.

## E. Семантика и доступность

- [ ] `lang=ru`, один H1, логичная иерархия заголовков.
- [ ] Навигация, main и footer имеют соответствующие элементы.
- [ ] Есть skip link и видимый focus.
- [ ] У полей настоящие label; placeholders не единственная подпись.
- [ ] Ошибки связаны с полем через ARIA.
- [ ] Изображения имеют корректные alt или пустой alt для декоративных.
- [ ] Текст/кнопки проверены на контраст; визуальные отличия при необходимой коррекции записаны.
- [ ] `prefers-reduced-motion` учтён.
- [ ] Нет невидимых ссылок на скриншоте, имитации форм и автоматического переноса фокуса без действия пользователя.

## F. Сборка и GitHub Pages

- [ ] `npm run check` фактически завершён без ошибок.
- [ ] `npm run build` фактически завершён без ошибок.
- [ ] Lockfile присутствует, версии среды записаны.
- [ ] В `dist` не скопированы документы, reference, QA и реальные файлы клиента.
- [ ] Все используемые изображения загрузились; у img naturalWidth > 0.
- [ ] Нет console errors и failed local requests на страницах.
- [ ] Проверена сборка с base `/spk-prototype/` или фактическим именем репозитория.
- [ ] Вложенная услуга открывается напрямую и после refresh.
- [ ] `404.html` существует и не превращает сайт в SPA-перенаправление.
- [ ] Prototype noindex присутствует на каждой странице; отсутствуют фиктивные Schema.org-данные.
- [ ] Workflow проверен; факт публикации отделён от успешной сборки.
- [ ] Домен и почта не подключены без отдельной команды.

## H. Передача

`qa/REPORT.md`: дата, версия среды, выполненные команды и результаты, ссылки/пути скриншотов, известные дефекты, ограничения исходников. README: запуск, сборка, публикация, места редактирования. Не ставить галочки за непроверенные пункты.
